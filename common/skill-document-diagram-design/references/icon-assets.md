# 圖示素材：向量線稿 vs 彩色/寫實風格

圖表裡要放「裝置/物件圖示」（筆電、螢幕、喇叭、手機……）時，有兩種本質不同的做法，不要混為一談。選錯模式、或兩種混用在同一張圖裡，都會破壞 `style-guide.md` 的克制美學。

## 兩種模式

| | 向量線稿圖示 | 彩色/寫實風格圖示 |
|---|---|---|
| 本質 | 向量 `<path>`，單色線條 | 點陣圖片（PNG/JPG），有自己的多色調色盤 |
| 嵌入方式 | inline `<path>`，`stroke="var(--ink)"` | `<image href="data:image/png;base64,...">` |
| 來源 | 圖示庫的 SVG 原始碼（Tabler Icons、Simple Icons，MIT/CC0） | 真正的小張點陣圖片素材（例如 Twemoji PNG，CC-BY 4.0）或使用者提供的圖片檔 |
| 何時用 | **預設選項**，符合 diagram-design 克制美學 | 只在使用者明確要求「real image icon」「寫實風格」「彩色圖示」時才用 |
| 對色彩系統的影響 | 完全遵守單一 accent color 規則，圖示只用 ink 一色 | 圖示本身自帶顏色，允許例外於「單一 accent color」規則——但只限圖示本身，其餘節點/連線/分區顏色仍照常規（見下方設計紀律） |

判斷準則很單純：使用者沒特別說時，一律用向量線稿；使用者明確說「real image」「寫實」「彩色圖示」等字眼時，才切換成點陣圖片模式。不要自己揣測使用者想要哪一種——如果不確定，直接問。

## 模式一：向量線稿圖示

1. 到 Tabler Icons（`https://raw.githubusercontent.com/tabler/tabler-icons/main/icons/outline/<name>.svg`，MIT）或 Simple Icons（CC0，品牌 logo 用）抓對應圖示的原始 SVG。
2. 只取其中的 `<path>`（或其他形狀元素），丟掉外層 `<svg>` 標籤本身的屬性。
3. 包一個 `<g transform="translate(x,y) scale(s)">` 放進圖表，`stroke="var(--ink)"`、`fill="none"`。

**關鍵陷阱（务必注意）**：來源圖示通常是 24×24 viewBox、`stroke-width="2"`。放進 `<g>` 用 `scale(s)` 放大後，`stroke-width` 也會被等比放大——如果照抄原始的 `2` 不改，縮放 3–4 倍後線寬會變成 6–8px，遠比圖表其他 1px hairline 線條粗，視覺上會又粗又搶眼，整張圖失去一致的克制感（這是實際踩過的坑，v4 第一版就是這樣，後來才修正）。

正確做法：先決定圖示縮放後**看起來**的線寬要接近圖表其他線條（通常抓 1.5–2px），反推 `stroke-width` 屬性值：

```text
stroke-width（屬性值）= 目標視覺線寬 ÷ scale
```

例如 `scale(3.4)`、目標視覺線寬 1.8px，則 `stroke-width="0.53"`。每個圖示縮放倍率不同，這個值要分別算，不能整批複製同一個數字。

## 模式二：彩色/寫實風格圖示（點陣圖片）

1. 找一組授權清楚、可直接抓到單張小圖檔的圖示素材。目前驗證可用的來源：**Twemoji PNG**（CC-BY 4.0），透過 jsdelivr 的 GitHub proxy 直接抓單張 72×72 PNG：
   ```text
   https://cdn.jsdelivr.net/gh/twitter/twemoji@<version>/assets/72x72/<hex-codepoint>.png
   ```
   codepoint 用目標 emoji 的 Unicode 十六進位（例如 laptop 💻 = `1f4bb`）。抓之前先用 `curl -s -o /dev/null -w "%{http_code}"` 確認檔名對不對（部分 emoji 檔名不含變體選擇符 `-fe0f`，抓錯會 404）。
   若使用者直接提供圖片檔，優先用使用者的檔案，不必再去找 emoji 圖庫。
2. 下載到本機，`base64 -w0 <file>.png > <file>.b64` 轉成單行 base64。
3. **用程式（Python/腳本）把 base64 字串寫進 SVG，不要手動複製貼上**——手動貼容易漏字元/斷行，導致 base64 損毀，瀏覽器只會顯示「圖片壞掉」的預設圖示且不一定報錯，很難第一時間發現。写完一定要重新渲染成 PNG 肉眼確認每個圖示都正常顯示，不能只檢查 XML 格式合法。
4. 嵌入方式：
   ```html
   <image x="{x}" y="{y}" width="{w}" height="{h}"
          href="data:image/png;base64,{base64}"/>
   ```
5. 在圖示上方加一行 HTML 註解標明來源與授權（比照向量圖示的慣例），例如：
   ```html
   <!-- laptop icon: real image (Twemoji "laptop" U+1F4BB, CC-BY 4.0, twemoji.twitter.com) -->
   ```

### 即使換成彩色圖示，設計紀律仍然適用

彩色/寫實圖示天生會帶自己的多色調色盤，這是它存在的目的（使用者明確要這種視覺），但不代表可以放棄其餘的克制原則：

- **只用在讀者一眼就該認出的實體物件/裝置**（筆電、螢幕、麥克風、人物頭像……），內部抽象節點（服務、模組、資料流）一律維持 `style-guide.md` 的素色矩形，不要也換成圖片，否則整張圖會变成「贴纸拼贴」。
- **圖示數量克制、尺寸統一**：同一張圖裡的圖示盡量用同一組尺寸網格（例如全部 64px 或全部 84px），讀起來才像同一套系統，不是隨手贴上去的雜牌圖示。
- **不要为了配合圖示顏色，反過來把圖表其他元素也上色**——節點、連線、分區仍然是單一 accent + 中性 ink/muted，色彩對比只留給圖示本身，維持「讀者第一眼該看的東西」的克制原則不變。
- **同一張圖裡不要混用向量線稿與彩色點陣圖示**——選一種模式，整張圖保持一致；如果同時有「內部節點用線稿 icon、外部裝置用彩色圖片」這種需求，那也是預先想清楚的設計決定，不是隨機混搭。

## 兩者可以並存於同一個技能輸出資料夾

同一個圖表如果先後產出過「向量線稿版」與「彩色寫實版」（例如使用者一開始要線稿，後來又要求換成真實圖片），兩份 `.html`/`.svg`/`.pptx` 可以並存（例如 `v4`＝線稿、`v5`＝彩色圖片），不需要互相覆蓋，方便使用者比較兩種風格再決定要哪一種。
