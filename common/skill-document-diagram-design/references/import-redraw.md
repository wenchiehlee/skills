# 匯入與重繪（Import & Redraw）

輸入不是「從零描述需求」，而是「這裡已經有一張圖，照它的語意重畫成本技能的風格」時，走這個流程。三種來源，處理方式不同：

| 來源 | 判斷方式 | 處理方式 |
|---|---|---|
| PlantUML / Mermaid 純文字 | `.puml`/`.planuml`/`.mmd`，或 Markdown 內的 ` ```mermaid ` 區塊 | 用腳本解析成 IR（見下） |
| 圖片（PNG/JPG/截圖） | 使用者直接丟一張圖檔 | Claude 用 Read 工具直接讀圖，人工判讀語意（見下） |
| 既有 SVG/HTML | 已經是向量/標記格式 | 直接讀取原始碼判讀結構，不需要額外解析工具 |

不論哪種來源，最終產出都是原生 HTML+SVG（依 `diagram-types.md` 選型、`style-guide.md` 定樣式），舊格式一律視為「這次要淘汰的東西」，不是輸出選項。

## 文字 DSL 來源（PlantUML / Mermaid）

- PlantUML mindmap：用 `scripts/import_plantuml_mindmap.py` 解析成 IR JSON（節點文字、粗體、顏色、左右側、階層）。
- 其他 PlantUML 圖型或 Mermaid：目前沒有專屬解析腳本，先由 Claude 直接讀懂該 DSL 語法（結構化文字，人類/LLM 判讀成本低），手動列出節點與關係清單，格式比照 `import_plantuml_mindmap.py` 的 IR（`type`/節點陣列/`children`），再依此清單手刻 SVG。若某類型匯入需求變得頻繁，比照 `import_plantuml_mindmap.py` 的模式另外寫一支專屬解析腳本。

## 圖片來源（PNG/JPG）

流程：

1. **讀圖**：用 Read 工具開啟圖片，直接視覺判讀——不要嘗試寫 OCR/CV 腳本做這件事，Claude 本身是多模態，人工判讀比寫影像辨識程式碼可靠且省事。
2. **列語意清單**：把圖裡看到的節點、分組、連線方向、標籤文字、大致階層/流程順序寫成一份條列清單（可比照 `import_plantuml_mindmap.py` 的 IR 結構，也可以是簡單的 bullet list，視圖表複雜度而定）。看不清楚或有歧義的地方（例如某條線的方向、某個縮寫的全名）明確列出來問使用者，不要用自信語氣腦補。
3. **決定細節/受眾 dial**（比照 diagram-design 原始方法論）：
   - **細節**：`faithful`（盡量保留原圖所有節點，上限抓 diagram-types.md 該類型建議上限的上緣）／`balanced`（原圖上限的一半左右）／`simplified`（只留骨幹，≤7 個節點）。沒特別說明時預設 `balanced`。
   - **受眾**：`engineer`（保留技術術語）／`mixed`／`executive`（術語換成商業語言）。只影響用詞，不影響節點數。
4. **確認語意清單**：把第 2 步的清單（含細節/受眾 dial 的選擇）回報給使用者確認，避免重畫出來的圖跟原圖語意有落差才發現。
5. **重畫**：確認後才依清單手刻原生 HTML+SVG。
6. **保真度紀錄（選用，圖表複雜或有明顯取捨時才做）**：一段話說明哪些節點被合併/簡化/捨棄，讓使用者知道新圖跟原圖的落差在哪，不需要另建檔案，寫在回覆裡即可。

## 既有 SVG/HTML 來源

直接讀取檔案內容，判讀其中的節點/群組/座標語意（若是別人手刻或工具匯出的 SVG，結構可能很雜亂，不需要保留其座標系統或分組方式，只取語意），流程同「文字 DSL 來源」——列語意清單、視需要確認，再依本技能的風格重畫，不要直接拿舊 SVG 改色改字。
