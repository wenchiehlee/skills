# 台灣裁判書查詢技能 (tw-court-records-search)

| 項目 | 內容 |
| :--- | :--- |
| 版本 | 1.0.0（詳見 `metadata.json`） |
| 登錄庫 | https://github.com/wenchiehlee/skills （`common/skill-tw-court-records-search`） |
| 維護者 | wenchiehlee |

依人名/公司名或一篇新聞，查詢台灣公開的裁判書與訴訟紀錄，輸出附信心分級與來源的結果表。這是一個純查詢/彙整技能，不做風險評估或身分脈絡建構——需要完整法律查核報告時請改用 `skill-tw-person-legal-check`（本技能是它的底層查詢層）。

## 資料來源

1. **司法院法學資料檢索系統（裁判書查詢）**——涵蓋各級法院民事/刑事/行政裁判書全文，是最權威的來源。但其查詢介面通常需要圖形驗證碼才能執行進階查詢，無法純程式化批次抓取。遇到驗證碼時，改用瀏覽器工具（例如 chrome-devtools）由人工協助完成查詢動作，或請使用者自行貼上查詢結果；**不得嘗試自動辨識或繞過驗證碼**。
2. **搜尋引擎 site-restricted 搜尋**（如 `site:judicial.gov.tw <姓名>`）——因裁判書全文常被搜尋引擎收錄，可作第一層快篩。缺點是只涵蓋已被索引的部分，且連結內容可能已下架或更新，須標記為「未驗證原文」直到實際開啟確認。
3. **新聞媒體報導**——案件當事人、案由、法院、審級等細節常見於司法/社會新聞，用來萃取查詢關鍵字（案號/法院/日期），也用來交叉驗證裁判書內容與新聞描述是否指向同一案件。
4. **各地方法院/高等法院官網公告**——可補充查詢進行中案件的開庭排程，但通常沒有裁判內容本身。

依法規定，公開版裁判書會遮蔽當事人身分證字號、未成年人與性侵害案件當事人姓名等個資。**本技能不得嘗試回推或補齊被遮蔽的個資。**

## Inputs

至少需要下列其中一種：

- **人名**：建議提供全名；若為常見姓名，必須同時提供至少一項可用於比對的輔助資訊（年齡、職稱、任職公司、居住地區、案件關鍵字），否則查詢結果只能標記為「同名不確定」
- **一篇新聞**：連結或全文，用於萃取查詢關鍵字

## 查詢流程

1. **正規化查詢對象**
   - 輸入是新聞時：萃取當事人姓名、法院名稱、案號（若有）、案由關鍵字、報導日期。
   - 輸入是人名時：記錄任何可用於後續比對的輔助資訊（公司、職稱、年齡、地區）。

2. **裁判書全文查詢**
   - 優先嘗試司法院裁判書查詢系統（注意 CAPTCHA 限制，必要時走人工協助流程）。
   - 平行用 site-restricted 搜尋引擎查詢，作為交叉驗證與快篩。
   - 記錄每筆結果：案號、法院、裁判日期、案由、當事人角色（原告/被告/上訴人/被上訴人/相對人等）、來源連結。

3. **身分比對與信心分級**
   - **高**：姓名相符 + 至少一項輔助資訊（公司/職稱/地區/案件關鍵字）也相符
   - **中**：姓名相符，且有其他來源（如新聞）佐證此案件與查詢對象相關，但輔助資訊未完全確認
   - **低**：僅姓名相符，無法排除同名不同人——輸出時必須明確標註「同名不確定，不代表為同一人」

4. **審級與確定狀態**
   - 明確標示一審/二審/三審，以及該裁判是否已確定（若來源有標示）。
   - 在確認裁判已定讞或已生效前，不得使用「已判刑」「已定罪」「敗訴確定」等斷定性用語，改用「經一審判決」「遭起訴」等中性描述。

## Output Format

輸出繁體中文表格，至少包含欄位：

| 案號 | 法院 | 裁判日期 | 案由 | 當事人角色 | 比對信心 | 審級/確定狀態 | 來源連結 |
|---|---|---|---|---|---|---|---|

並附上：

- 查詢關鍵字與比對依據說明
- 未能查得結果時，明確說明已嘗試的管道與限制（例如：「司法院查詢系統需人工輸入驗證碼，本次僅完成搜尋引擎快篩」）

## Evidence Rules

- 不得繞過司法院查詢系統的驗證碼或其他反爬蟲/存取控制機制；需要圖形驗證碼時改走人工協助或替代管道。
- 不得嘗試還原依法遮蔽的個資（身分證字號、未成年人/性侵害案件當事人姓名等）。
- 「低」信心比對結果一律標註「同名不確定」，不得直接歸屬給查詢對象。
- 不得將「被告」「遭起訴」等同於「有罪」；未確定案件一律使用中性描述。
- 每筆重要結論需附來源連結；若僅來自搜尋引擎摘要而未實際開啟原文查證，需標明「未驗證原文」。
