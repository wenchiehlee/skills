# 台灣人物法律查核主控台 (tw-legal-search-console)

本 skill 是本地整合層，自給自足地定義風險分級與輸出格式規則（不依賴外部 skill 動態載入），
執行時串接：

- [`skill-tw-legal-rag`](../skill-tw-legal-rag/SKILL.md) — 裁判書檢索層（呼叫 `twlegalrag pack`，取得含
  `citation_id` / `allowed_citations` / `fulltext_excerpt` / `case_history` 的 bundle，取代人工繞驗證碼
  查司法院網站的做法）。此為**主要**裁判書來源。
- **司法院裁判書系統即時備援查詢**（`judgment.judicial.gov.tw`，透過 chrome-devtools 互動查詢）——當
  tw-legal-rag 查無結果、且案件為近期（數日至數月內）宣判的即時案件時使用，見下方「即時案件備援檢索」。
- 內建 web search — 新聞與（如為上市櫃經營層）公開資訊觀測站重大訊息佐證

## 兩種輸入模式

### 模式一：新聞連結

輸入例：`https://tw.news.yahoo.com/...`

1. WebFetch 該連結，擷取：當事人姓名（若多位，選報導主角；新聞常僅揭露姓氏，如「彭姓男子」——如此
   應照實記錄為「姓氏已知、全名未知」，不得臆測全名）、職稱/任職公司、案由關鍵字、報導日期（**與今日
   日期比較，若報導日期在近期內〔數日至數月〕，本案屬於「即時案件」，應優先評估是否需要啟用即時案件
   備援檢索**）、地區線索。
2. 進入下方共同流程，以擷取到的姓名 + 脈絡作為查詢輸入。

### 模式二：姓名搜尋

輸入例：`xxx 桃園`（姓名 + 輔助識別資訊，如地區/公司/職稱/年齡）

- 若使用者只給姓名、未給輔助資訊：直接進入共同流程，但最終比對信心上限為「低」，並在報告中明確提示
  「建議提供地區/任職公司等資訊以提高比對準確度」。

## 共同流程

1. **建立人物識別脈絡**：全名（若僅知姓氏，明確記錄為部分姓名）、常見別名（如有）、任職公司/職稱、
   地區等輔助資訊、報導/查詢日期。

2. **裁判書檢索**（呼叫 `skill-tw-legal-rag`，主要來源）：

   ```bash
   python ../skill-tw-legal-rag/scripts/search_judgments.py "<姓名> <輔助關鍵字，如地區/案由>" -n 8
   ```

   - 只能引用回傳 bundle 的 `allowed_citations` 內的 `citation_id`；`unread_candidates` 不得引為權威。
   - 每筆結果記錄：`citation_text`（法院/年度/字號/案由類別）、`jdate`、`case_category`、`hit_excerpt`、
     `case_history`（是否已被上級審廢棄/駁回）、`citation_url`。
   - 姓名為常見姓名時，`-n` 可提高到 8-10 筆以涵蓋更多候選，逐筆做身分比對。
   - **語義檢索假陽性警示**：tw-legal-rag 是語義+詞彙混合檢索，回傳結果常包含姓名**形近/音近但字元不同**
     的其他人（例如查「王小明」混入「王小名」「王少明」；查「陳大文」混入其他罕見姓名）。逐筆核對
     `fulltext_excerpt` 中被告/當事人的**完整姓名字元**是否與查詢對象完全一致，不一致者直接排除，不得
     計入任何比對信心等級。
   - 若姓名不完整（如新聞僅揭露姓氏）：不得單以姓氏做全文檢索比對信心，改以**案情特徵組合**（地區＋
     特殊作案手法/工具＋罪名關鍵字，如「泰山 球棒 侵入住宅 強制性交未遂」）檢索，逐筆核對案情細節
     （時間、地點、手法）是否與新聞描述吻合，而非核對姓名。

3. **即時案件備援檢索**（僅在步驟2查無結果、且案件屬近期宣判的「即時案件」時執行）：

   tw-legal-rag 資料庫的裁判書索引存在時間落差（尤其性侵害等需個資遮蔽後製的案件），對於**宣判後數日
   至數週內**的案件，步驟2極可能查無結果。此時不應直接判定「查無紀錄」，應改用 chrome-devtools 直接
   互動查詢司法院裁判書系統官方資料庫：

   a. 開啟 `https://judgment.judicial.gov.tw/FJUD/Default_AD.aspx`（複合欄位查詢頁）。
   b. 取得頁面 snapshot，於「案件類別」勾選對應類別（刑事/民事等）；若已知法院，於法院清單點選（可
      複選）；「裁判期間」欄位填入民國年（西元年－1911）＋報導日期前後的合理區間（例如報導於西元
      2026年8月31日，可設 115年08月25日至115年09月05日，涵蓋宣判到報導間的時間差）；「全文內容」
      欄位填入**最具識別度、最不可能重複的案情關鍵字**（優先序：特殊地點名稱/店家名〔如「小北百
      貨」〕＞特殊作案工具＋動作組合〔如「球棒」+「衣櫥」〕＞罪名全稱）；點擊「送出查詢」。
   c. 若查詢結果為 0 筆：放寬條件（擴大日期區間、移除法院限制、改用其他關鍵字組合）重試 1-2 次；
      仍查無結果則依「無法比對（資料庫索引延遲）」呈報，不得臆測案號或姓名。
   d. 若查詢結果筆數過多（不具區辨力）：加入更多關鍵字或收斂法院/日期範圍後重試。
   e. 命中候選判決後，開啟判決全文連結（`data.aspx?ty=JD&id=...`），逐項核對犯罪事實段落是否與新聞
      報導的時間、地點、手法、當事人關係完全吻合，吻合視為找到即時案件的正式判決來源。
   f. 找到全文後記錄：完整案號、裁判日期、被告姓名（若判決書正文揭露全名，優先採用；若僅代號如
      「Ａ０６」，記錄「判決書亦未揭露全名」）、起訴案號、罪名與宣告刑（含附表）、案件審理歷程
      （頁面下方「歷審裁判」區塊，含是否已上訴、上訴審案號）、來源連結（判決書頁面實際 URL，不得
      自行拼湊 `id` 參數）。
   g. **此路徑取得的判決全文視為與 tw-legal-rag bundle 同等權威**，可直接引用於報告，並於「裁判書
      查詢結果」表格的「來源」欄位標註為「司法院裁判書系統（即時查詢）」以區別於 tw-legal-rag。
   h. 案號年度提醒：民事/刑事案號年度通常對應**起訴/受理年度**而非宣判年度，若初次查詢用宣判年度
      無結果，應同時嘗試起訴年度（宣判年度或前一年度）。
   i. 此流程僅適用於**近期案件的存在性/內容確認**，不得用於大量姓名的批次背景調查（效率遠低於
      tw-legal-rag 語義檢索，且互動查詢對司法院系統造成負載，應合理節制查詢次數）。

4. **多筆候選裁判書分組（同名不同人聚類）**：當同一查詢回傳多筆姓名相符的裁判書時，先分組再逐組評分：
   - 分組依據（依可靠度排序）：①案號彼此明確互相引用（如撤緩裁定引用前案案號）→ 同組且信心「高」；
     ②`case_history` 記載的上下審級關聯 → 同組；③裁判書內文揭露的年齡、住所、任職公司等身分細節相符
     → 同組；④僅法院轄區/時間相近 → 弱關聯，不足以合併，須標註「無法判斷是否同一人」。
   - 裁判書起訴書附件有時會揭露當事人性別、年齡、戶籍/住居所（身分證字號等已依法遮蔽），優先讀取
     `fulltext_excerpt` 中的「被告」欄位附近文字尋找此類資訊，但注意**核對該資訊描述的對象是哪一位
     被告**（多被告案件中，量刑減輕段落提到的年齡等資訊可能屬於同案其他被告，不可逕自歸給查詢對象）。
   - 分組結果無法合併的各組，彼此之間比對信心一律「低（同名不確定）」，即使某一組內部信心「高」。

5. **身分比對與信心分級**（套用在上一步分組後、屬同一人的裁判書集合上）：
   - **高**：姓名相符 + 至少一項輔助資訊（法院所在地區、案由與新聞描述相符、任職公司等）也相符；或
     （即時案件備援檢索路徑）判決全文之犯罪事實與新聞報導的時間、地點、手法細節高度吻合。
   - **中**：姓名相符，且有新聞佐證此案件與查詢對象相關，但輔助資訊未完全確認。
   - **低**：僅姓名相符，無法排除同名不同人——輸出時必須明確標註「同名不確定，不代表為同一人」。
   - `case_history` 顯示該裁判已於上級審被廢棄/駁回時，須在報告中註明，不得當成現行有效見解引用。

6. **新聞與公開資訊佐證**：
   - web search「姓名 + 起訴/判決/涉訟/背信/掏空/內線交易/違反證交法」等關鍵字。
   - 若查得此人為上市櫃公司負責人/經營層（可先用「姓名 + 董事長/總經理」等關鍵字快篩確認職務），
     查詢公開資訊觀測站（MOPS）重大訊息；純公司對公司的商業契約訴訟（如給付貨款/開發費）不等於
     個人重大經濟犯罪，須在報告中明確區分「公司訴訟」與「個人涉訟」。
   - 交叉比對新聞內容與步驟 2-5 的分組結果，確認是否指向同一案件；用來提升或修正比對信心。

7. **風險分級**：
   - **高**：明確指向此人、已進入司法程序（起訴/一審以上）、案由涉及背信/詐欺/掏空/證券違規/性自主
     等重大犯罪。
   - **中**：民事訴訟紀錄（債務糾紛、契約爭議），或案由不明確但同名+輔助資訊部分相符。
   - **低**：僅同名裁判書但輔助資訊不相符/無法比對，或僅未經證實的新聞傳聞。
   - **無明顯風險**：查無相關公開紀錄——需註明搜尋範圍與限制，不得宣稱「保證乾淨」。
   - **無法分級（資料庫索引延遲）**：即時案件經步驟3備援檢索仍查無結果時使用，須註明已嘗試的查詢
     條件與建議的後續查詢時機（例如「建議數週後重新查詢」）。

## Output Format

繁體中文報告：

1. `輸入模式` — 新聞連結 或 姓名搜尋，以及擷取/輸入的識別資訊；若為即時案件，註明報導日期與今日
   日期的相對關係
2. `人物識別` — 姓名、別名、任職公司/職稱、比對依據
3. `裁判書查詢結果`（表格，需標明資料來源）：

   | citation_id / 案號 | 法院 | 案號 | 裁判日期 | 案由/類別 | 比對信心 | 審級/確定狀態 | 資料來源 | 來源連結 |
   |---|---|---|---|---|---|---|---|---|

   「資料來源」欄位填「tw-legal-rag」或「司法院裁判書系統（即時查詢）」。

4. `新聞與公開資訊佐證` — 來源、日期、摘要，以及與裁判書查詢結果的對應關係
5. `風險分級` — 分級 + 理由 + 不確定性說明
6. `引用來源` — 全部連結；tw-legal-rag 來源的裁判書連結一律取自 bundle 的 `citation_url`（不得自行
   拼湊），司法院即時查詢來源的連結一律取自實際開啟的判決頁面 URL（不得自行拼湊 `id` 參數），新聞
   連結標明是否已實際開啟驗證原文

## Evidence Rules

- 裁判書引用僅限 `skill-tw-legal-rag` 回傳 bundle 的 `allowed_citations`，或即時案件備援檢索中**實際
  開啟並讀取全文**的司法院裁判書系統頁面；不得捏造或回憶案號，不得憑猜測的年度/字別組合直接引用未經
  開啟驗證的案號。
- 不得繞過司法院查詢系統的驗證碼；一般裁判書查詢（`Default_AD.aspx` 複合欄位查詢與判決全文頁）不需要
  驗證碼即可存取，tw-legal-rag 亦為預先索引的合法公開資料檢索服務，兩者皆無需繞過任何驗證機制。
- 即時案件備援檢索應合理節制查詢次數（每案建議 3-5 次互動查詢內應能命中或判定查無結果），不得對司法
  院系統進行大量或高頻率的自動化查詢。
- 不得嘗試回推依法遮蔽的個資（身分證字號、未成年人/性侵害案件當事人姓名等）；若判決正文本身已合法
  公開被告全名（如非性侵害案件，或性侵害案件判決正文選擇揭露被告姓名而僅遮蔽被害人代號），可如實
  引用，不視為回推遮蔽個資。
- 不得將「被告」「遭起訴」等同於「有罪」；未確定案件一律使用中性描述。
- 「低」信心比對結果一律標註「同名不確定」，不得直接歸屬給查詢對象。
- 本報告非正式徵信/良民證文件，需在報告中註明「僅供內部參考，非正式法律或徵信文件，正式用途請洽律師或
  申請良民證/警察刑事紀錄證明」。
- tw-legal-rag 後端可能記錄查詢字串供檢索品質分析，僅送出公開身分資訊（姓名+公開脈絡），不得送出機密
  資料；司法院裁判書系統查詢同樣僅送出公開身分/案情關鍵字。
